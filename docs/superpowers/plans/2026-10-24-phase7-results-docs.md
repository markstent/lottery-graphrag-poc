# Phase 7: Results Screen, Copy Pass and Documentation Cut Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the full Results screen on published benchmark runs, finish the product copy pass, and cut the repository documentation to ten primary files, ready for the CP3 official-run proposal.

**Architecture:** The backend publishes everything Results shows: a typed `summary.json`, a new per-instance results route built from `results.json`, a job list for reattaching to a running benchmark, and one new harness output (the ontology-dependent split) that spec 7.5 asks for.
The frontend never computes a statistic.
Pure modules in `src/results/` turn API responses into chart rows and table rows, and the screen composes Phase 5 chart primitives and Phase 6 parts.
The documentation cut moves history to `docs/reference/` with `git mv`, merges current material into ten primary files, and a test keeps every relative link valid.

**Tech Stack:** Python 3.13, FastAPI, Pydantic; React 19, TypeScript strict, Tailwind v4 tokens, Vitest with RTL, Playwright.
No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-overhaul-design.md`, sections 5.5 (statistics and reporting), 7.1, 7.5, 7.8, 7.9, 8 and section 9 step 7.
CP2 approvals in `HITL_STATUS.md` and `DECISIONS.md` D-033 to D-059 bind this plan, in particular D-048 (no interval on per-approach tiles).

## Global Constraints

- Everything in `AGENTS.md` applies, and so do the Global Constraints of the Phase 5 and Phase 6 plans: tokens, pipeline names "Text search", "Graph", "Graph + Ontology" always with the letter, banned words, states, accessibility, lean code, British spelling, no em dashes, no co-author lines, never push.
- No number appears on screen unless the harness produced it and the API published it (spec anti-goal). The frontend never recomputes a score, mean, delta or interval (spec 5.5 "Reporting").
- A quick check (smoke) run is never shown as a result: no charts, no tiles, no table scores; only its headline and its reproducibility record.
- A subset official run carries a visible "Subset run" label beside every chart and table that shows its numbers.
- Per-approach tiles carry no interval (D-048, approved). Intervals appear only on paired differences.
- Only `app/api/benchmarks.py` and `app/api/scoring.py` may import `app.evaluation` (D-035); the isolation tests keep passing unchanged.
- No route or payload carries expected answers, claims or checks except `QuestionOut`, which already does for Help (owner decision).
- Neo4j stays at dev-seed2026 with 36,888 nodes. No task ingests, wipes or starts a benchmark against the live graph. Tests use the fake generator and temporary run directories.
- `docs/evaluation/question-bank.md` is generated by its CLI and is never edited or moved by hand. `CHANGELOG.md` is never edited by hand.
- Copy budget outside Help stays within the test cap of 1,300 words, with Results included; the target is about 1,200 (spec 7.8). Help stays within 1,650.
- Each screen opens with its purpose sentence and nothing else before the content. Results' purpose sentence is "Every official run, every question, every score, with intervals."
- Visual baselines cover every Results state at 1920x1080 and in presentation mode, regenerated on this machine.
- Frontend commands run inside `frontend/` as `node ~/.cache/node/corepack/v1/pnpm/12.14.0/bin/pnpm.mjs <script>`; Playwright as `node node_modules/@playwright/test/cli.js test` (visual: `--config playwright.visual.config.ts`).
- Model policy for execution: Sonnet implementers and routine reviews; Opus reviews for Task 1 (statistics) and Task 2 (API and isolation), and for the final whole-branch review.

## Review Focus

1. A benchmark job is running and the reader reloads Results or goes to another screen and back. The progress must reappear and Cancel must still work. Test: `reattaches to a running job after reload` (Task 6).
2. The selected run is the 150-instance smoke run. No score, chart or tile may appear; the headline and the reproducibility record do. Test: `quick check shows no results` (Task 4).
3. An older run lacks fields added later (`git_dirty`, `graph_label_version`, `judge_temperature`, `generation_reasoning`, `ontology_split`). The screen must show "Not recorded" for each and render everything else. Test: `older run renders with missing fields` (Tasks 2 and 5).
4. A per-question row belongs to world 2027, which is not the loaded world. It must not offer Live Lab; it says why. A world-2026 row without a recording must open Live Lab with the question chosen and not started. Test: `live lab link only for the loaded world` (Tasks 5 and 6).
5. Every comparison in the run is "too few pairs" (the real `pilot-2026-nothink` run). The interval chart must say so per row and draw no interval, and no delta appears as a result. Test: `too few pairs draws no interval` (Task 4).

### Task 1: Ontology-dependent split in the harness

Spec 7.5 asks for "B versus C on the `ontology_dependent` questions and on the rest".
`ontology_dependent` is not the same as stratum H2: in `pilot-2026-nothink`, two H5 instances are ontology-dependent.
So the split is a new harness output, computed with the approved cluster bootstrap and outside the Holm family.

**Files:**
- Modify: `backend/app/evaluation/report.py` (`summarize`, `_comparisons`, `render_report`).
- Modify: `docs/evaluation/statistics.md` (new section "Ontology-dependent split").
- Test: `backend/tests/test_evaluation_report.py` (or the existing summary test module; add to whichever holds `summarize` tests).

**Interfaces:**
- Produces `summary["ontology_split"]`: a list of 8 cells, each `{group: "ontology_dependent" | "other", metric: "evidence_f1" | "answer", comparison: "B_vs_A" | "C_vs_B", n, clusters, mean, low, high, p: null, p_holm: null, in_family: false, reason: "not_in_family" | "too_few"}`.
  - `reason` is `"too_few"` when the pairs gate or the groups gate (`MIN_PAIRS_FOR_CLAIM`, `MIN_CLUSTERS_FOR_CLAIM`) fails, else `"not_in_family"`.
  - The interval is computed whenever there is at least one pair, exactly as `_comparisons` does for strata.
  - Group membership comes from `instance.ontology_dependent`, across all strata.
- Produces `instance_means(result: InstanceResult) -> dict[str, dict[str, float | None]]`: per pipeline, the mean over successful repeats of every metric in `METRICS`, using the same extractors `_observe` uses. `_observe` calls it, so there is one definition of the observation.
- `SUMMARY_SCHEMA_VERSION` stays "2": the key is additive, and readers treat it as optional.
