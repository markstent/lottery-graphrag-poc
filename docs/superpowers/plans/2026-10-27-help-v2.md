# Help v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the Help screen as a one-stop guide with a Plain and a Technical reading level, twelve chapters, live settings, and every assumption and limit stated.

**Architecture:** One read-only endpoint, `GET /api/v1/settings`, returns the settings a run records, built by the same function the runner uses.
Help holds each chapter's copy as data with separate `plain` and `technical` fields, renders the level chosen by a switch, and fills current settings from the endpoint and recorded ones from the newest official run.
The banned-word scan reads the `plain` fields only, and the Help word cap is removed.

**Tech Stack:** Python 3.12, FastAPI, pytest; React, TypeScript strict, Vitest, React Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-26-help-v2-design.md` (approved by the owner, "continue", 2026-10-26).

## Review Focus

1. A deep link from another screen (`#/help?section=stories&story=SCN-007`, `?section=scoring`, `?stratum=H2`) lands on the wrong chapter or no longer marks the story: pinned by the alias tests in Task 2.
2. The settings endpoint fails or is slow: Help must still render every chapter, with settings cells reading "Not available" and a retry, not a blank screen: pinned in Task 2.
3. The newest official run lacks a field the current settings have, or differs: the cell reads "Not recorded" or is marked different, never a wrong value: pinned in Task 2.
4. Local storage throws (private window): the level falls back to Plain with no error: pinned in Task 2.
5. A number typed into prose drifts from the code: Task 3 and 4 tests assert that prose settings come from the settings object, and the accuracy review in Task 6 traces every claim.

**Interfaces:**
- Produces:
  - `type Level = 'plain' | 'technical'`; `useLevel(): [Level, (level: Level) => void]` reading `?level=` first, then local storage key `help-level` (ignored in presentation mode), default `'plain'`; writes both on change; storage errors swallowed to the default.
  - `CHAPTERS`: twelve `{ id, nav, title }` in this order and with these ids: `why`, `company`, `stories`, `approaches`, `evidence`, `answer`, `scoring`, `results`, `limits`, `questions`, `glossary`, `running`.

  - `type ChapterCopy = { plain: readonly Block[]; technical: readonly Block[] }` where `Block` is a paragraph string, a list of strings, a settings table (`{ kind: 'settings'; keys: readonly SettingKey[] }`) or a named diagram (`{ kind: 'diagram'; name: DiagramName }`).
  - `useSettings()` loading `/api/v1/settings`, and `settingValue(key)` returning current, recorded (newest official run) and whether they differ.
  - `<Chapter id copy={ChapterCopy}>` rendering Plain blocks, and at Technical the Plain blocks followed by the Technical blocks under a "Technical detail" subheading.
- Consumes: Task 1's `ExperimentSettings` type.
