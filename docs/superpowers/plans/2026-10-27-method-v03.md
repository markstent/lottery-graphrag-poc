# Method v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v0.2 evidence method with method v0.3 (graph ranks its own records, one token budget with no item limit, compact facts with a path line, fixed answer measures, a groundedness measure, a hand-labelled check of the measures), and prepare, without running them, the CP4 stop 1 runs on seed 2026.

**Architecture:** v0.3 replaces v0.2 in the code: one selection path, no flag back, the D-025/D-081 slot logic and its tests removed.
A keeps its hybrid search and cross-encoder; B and C order graph records by a tiered graph relevance rule and merge them with the document channel by alternation under the shared 2,000-token budget.
Every run records `method_version` "0.3.0" and the new rule, prompt, scorer and judge versions, so `compare` and resume refuse to pair v0.3 with v0.2 runs, which stay on disk and readable, labelled as the old method.

**Tech Stack:** Python 3.12, Pydantic, DuckDB, pytest, mypy, ruff; React 19, TypeScript strict, Vitest, React Testing Library, Playwright.

**Spec:** `docs/evaluation/v0.3-method-proposal.md`, approved by the owner on 2026-10-27 ("approve and continue", every section 6 recommendation), plus the owner's direction of 2026-10-27 relayed by the controller: "Best system, A as the baseline" (v0.3 replaces the old method; old-method-only tests go; run data stays; favour the choices that make C most accurate and grounded, with A a fair, well-tuned baseline).
Read the spec, `AGENTS.md`, `docs/retrieval.md` and `docs/evaluation.md` before any task.

2. A question whose target words match nothing, or match so broadly that every node is a target holder, must order the graph channel exactly as seeds then composite score (Task 8).
3. A single candidate bigger than the whole budget at the head of one channel must be refused as `context_budget` without stopping the other channel from filling the budget (Task 9).
